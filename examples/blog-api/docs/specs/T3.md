# T3: POST /auth/login + auth middleware

- Requirements: FR-2
- Depends on: T1
- Areas: auth

## Goal

Exchange credentials for a JWT, and provide the middleware that protects
routes (used by T4).

## Contract

- `POST /auth/login` per `operationId: login` in 04-api-spec.yaml.
- Token per ADR-0002: HS256, `sub` = user id, 1-hour expiry, secret from
  `JWT_SECRET`.
- `src/middleware/auth.ts` exports `requireAuth`, which sets `req.userId` or
  responds 401 with the `Error` shape.

## Acceptance tests

- `test/auth.login.test.ts` — 200 with valid token; identical 401 for wrong
  password and unknown email; middleware rejects expired, wrongly signed and
  `alg: none` tokens.

## Out of scope

Refresh tokens, logout, rate limiting.

## Notes

Compare against a dummy hash when the email is unknown so both failure paths
take similar time.
